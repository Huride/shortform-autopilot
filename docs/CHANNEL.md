# 채널 전략과 리스크

*확인 기준일: 2026-08-07.*

## 1. 성향은 코드가 아니라 설정이다

`channels/<id>.json` 하나가 채널 하나다. 파이프라인은 하나만 유지한다.

| 필드 | 역할 |
|---|---|
| `stance` | 논조. 대본 시스템 프롬프트에 그대로 들어간다 |
| `framing` | 이슈를 보는 렌즈. 대본이 잡을 각도를 결정한다 |
| `topicPreference` | 주제 선정 단계의 선호 |
| `guardrails` | 하지 않을 것. **채널 생존 장치** |
| `theme` | 시각 정체성 — 폰트·색·레이아웃·배경·진행 표시·후킹 |
| `voiceId` | ElevenLabs 목소리. 채널마다 달라야 한다 |
| `publishHour` | 발행 시각. 채널마다 어긋나야 한다 |
| `disclosure` | AI 생성 고지. 코드가 강제로 붙인다 |

`theme`·`voiceId`·`publishHour` 는 취향이 아니라 **§3-1 리스크 대응**이다.

반대 성향 채널 추가 = JSON 파일 하나. 코드 포크가 아니다.

## 2. 일일 편성 파이프라인

```
24시간 RSS 수집 (9개 매체, 좌·중·우)
   ↓
이슈 군집 + 점수 (Claude)
   ↓  coverage · leanCoverage · shortformFit · channelFit · freshness · duplicateRisk
1건 선정 (상위 5개는 사유와 함께 잡에 기록)
   ↓
사실 목록 추출 (Claude) — 기사에 실제로 있는 주장만, 출처 첨부
   ↓
대본 → 음성 → 렌더 → 발행
```

### 왜 좌·우를 다 수집하나

채널 논조와 무관한 **수집 품질** 문제다.

- 한쪽만 보면 이슈 자체를 놓친다. 상대 진영이 먼저 보도하는 사안이 있다.
- `leanCoverage`(좌·중·우가 모두 다뤘나)가 **실체 판정 신호**다. 한쪽만 다룬 사안은
  진영 이슈이거나 아직 검증되지 않았다는 뜻이고, 그걸 덥석 다루면 나중에 뒤집힌다.

### 사실 고정 (fact-lock)

대본 생성기는 **브리프의 `facts` 목록 밖의 사실을 말할 수 없다.** 각 사실에는 출처가 붙는다.

논조는 제약하지 않는다. 사실에 대한 **평가와 해석은 자유**고, 그게 채널의 색깔이다.
막는 건 사실 **자체를 지어내는 것**뿐이다.

`caution` 필드는 미확정 혐의·반론 지점을 담고, 대본은 이걸 반드시 유보적으로 표현한다.

## 3. 리스크 세 가지

### 3-1. 이중 채널 — 가장 큰 리스크

**같은 운영자가 대립하는 두 채널을 동시에 무인 운영하는 것은 플랫폼이
"coordinated inauthentic behavior"로 분류하는 정확한 정의다.**
정치 계정이 영구 정지되는 1순위 사유이고, Meta 는 이걸 분기별 위협 리포트로
공개할 만큼 집중 단속한다. 적발되면 **두 채널이 같이 죽는다 — 성공한 쪽까지.**

#### 연결고리는 강한 순서대로 이렇다

계정 분리와 업로드 시각 분리는 **가장 약한 축에 속한다.** 강한 것부터:

| 강도 | 신호 | 대응 |
|---|---|---|
| 최상 | **렌더 지문** — 같은 폰트·레이아웃·배경·전환·자막 스타일 | `theme` 로 분리 ✅ |
| 최상 | **TTS 음색** — 같은 목소리는 즉시 드러난다 | 채널별 `voiceId` ✅ |
| 상 | 결제수단·사업자 정보 | 운영자 몫 |
| 상 | 동일 Google Cloud 프로젝트 / Meta 앱 | 운영자 몫 |
| 중 | IP·기기 지문 | 운영자 몫 |
| 중 | 대본의 문장 습관 — 같은 프롬프트 골격이면 문체가 겹친다 | `stance`/`framing` 이 다르면 상당히 갈리지만 완전하지 않다 |
| 하 | 캡션·해시태그 구성 패턴 | 운영자 몫 |
| **하** | **업로드 시각** | `publishHour` ✅ |

`✅` 는 이 레포에서 처리한 항목이다. **나머지는 코드가 해줄 수 없다.**

#### 현재 두 채널의 시각 분리

| | right | left |
|---|---|---|
| 폰트 | BM 도현 (굵은 디스플레이) | 나눔명조 (세리프) |
| 배경 | 대각선 하드 스플릿 | 라디얼 그라디언트 |
| 자막 | 하단 좌측 정렬 + 붉은 블록 하이라이트 | 중앙 정렬 + 파란 글자 강조 |
| 제목 칩 | 없음 | 있음 |
| 진행 표시 | 점 | 바 |
| 후킹 | 상단 배너 | 전면 카드 |
| 발행 시각 | 08:00 | 19:00 |

⚠️ **폰트는 시스템 설치본에 의존한다.** 렌더러를 리눅스 서버로 옮기면 두 폰트 모두 없어
양쪽이 같은 기본 산세리프로 떨어진다 — 오류 없이 조용히. 그 순간 위 표의 첫 줄이 무너진다.
서버 이전 전에 폰트 파일을 `remotion/public/fonts/` 에 넣고 `@font-face` 로 고정할 것.
`pnpm doctor` 가 현재 설치 여부를 점검한다.

#### 그래도 남는 것

시각·음성·시각을 분리해도 **같은 파이프라인이 같은 뉴스 소스에서 같은 시각에 주제를 뽑는다.**
두 채널이 같은 날 같은 이슈를 반대 논조로 다루는 패턴이 반복되면 그 자체가 신호다.
채널마다 수집 시각을 어긋나게 하거나 `topicPreference` 를 크게 벌려두는 편이 낫다.

권하는 순서는 그대로다:

1. **1차 채널 하나를 제대로 키운다.** 지표가 안 나오면 2차도 의미 없다.
2. 2차는 **완전 분리** — 별도 계정·결제·기기·네트워크·API 프로젝트 + 위 시각 분리.
3. 또는 **단일 채널 + 양쪽 프레임 포맷** ("이 사안, 양쪽은 이렇게 본다").
   진영 결집력은 약하지만 진정성 리스크가 없고 두 청중을 다 가져간다.

### 3-2. 명예훼손

정보통신망법 제70조:

| | 요건 | 형량 |
|---|---|---|
| 1항 | 비방 목적 + **사실** 적시 | 3년 이하 징역 또는 3천만원 이하 벌금 |
| 2항 | 비방 목적 + **거짓** 사실 적시 | 7년 이하 징역 또는 5천만원 이하 벌금 |

반의사불벌죄라 피해자가 처벌을 원하지 않으면 처벌하지 않는다. 공적 인물의 공적 사안에
대해서는 공익성이 인정되면 '비방 목적'이 부정될 여지가 있다 — 하지만 그건 **재판까지 가서**
다투는 이야기다.

**자동 생성이라도 게시자 책임이다.** "AI가 썼다"는 항변이 되지 않는다.
그래서 fact-lock 과 `caution` 이 있다.

### 3-3. AI 표시 의무 · 선거법

| 규정 | 내용 | 현재 적용 |
|---|---|---|
| AI 기본법 (2026-01-22 시행) | AI 생성물 표시 의무, 위반 시 최대 3천만원 과태료 | 1년 이상 계도기간 — 실질 과태료는 2027년 이후 전망 |
| AI 기본법 (딥페이크) | 사람을 조작한 결과물 워터마크 | **계도기간 없이 즉시 단속** |
| 공직선거법 제82조의8 | 선거일 **90일 전 ~ 선거일** 딥페이크 선거운동 금지 | 7년 이하 징역 또는 5천만원 이하 벌금 |

**현재는 선거 비수기다.** 2026년 6·3 지방선거는 끝났고, 다음 전국선거(2028 총선)의
90일 규제 구간은 2028년 1월경부터다. 그 전에 캘린더에 표시해둘 것.

이 파이프라인은 **실존 인물의 얼굴·음성을 합성하지 않는다** (텍스트 + TTS + 모션그래픽
+ 추상 배경 이미지). 딥페이크 규정에 직접 걸리지 않는 이유이고, 이 선을 넘지 않는 것이 설계 의도다.

#### 배경 이미지의 제약

주제에 맞는 배경을 생성해 쓰지만, 프롬프트에 **코드가 강제로 붙이는** 제약이 있다:

- 사람·얼굴·인물 실루엣 금지 (군중·뒷모습 포함)
- 실사풍 금지 — 추상·상징 일러스트만
- 글자·숫자·로고·정당 상징·국기 금지
- 실존 인물이나 실제 사건 장면 재현 금지

정치 인물의 생성 이미지는 그 자체로 딥페이크 영역이고, 실사풍 '사건 재현'은
허위 정보로 읽힌다. 추상 상징은 두 문제가 모두 없으면서 시각적 효과는 그대로다.

제약은 프롬프트를 만드는 단계와 **분리해서** 코드에서 덧붙인다 —
모델이 만든 프롬프트가 제약을 흐리는 것을 막기 위해서다 (`src/pipeline/image.ts`).

AI 고지는 `withDisclosure()` 가 코드에서 강제로 붙인다. 모델이 빠뜨려도 들어간다 —
규정 준수가 모델의 준수 여부에 달려 있으면 안 된다.

## 4. 운영 수칙

- **하루 1편.** 늘리면 도달이 오르는 게 아니라 스팸 탐지에 걸린다.
- **같은 주제를 연속으로 다루지 않는다.** `duplicateRisk` 가 8 이상이면 경고가 뜬다.
- **출처를 고정 댓글에 붙인다.** `pnpm cli sources <id>` 가 붙여넣을 형태로 출력한다.
  분쟁이 생겼을 때 이게 방어선이다.
- **초기 N편은 발행 전에 사람이 읽는다.** `--dry-run` 으로 편성만 돌려보고,
  대본은 `data/jobs/<id>.json` 에서 확인한다.
- **강한 논조 ≠ 근거 없는 주장.** 전자는 채널을 키우고 후자는 채널을 죽인다.
  이 구분이 흐려지는 순간 위 리스크가 전부 현실이 된다.
